What This Is

A Business Development budgeting tool for multifamily projects. You enter the project's size, unit mix and income assumptions; the tool prices the construction scope from a shared, versioned rate library and rolls it up into two numbers that matter:

  • Contract sum — construction hard cost + profit + contingency. This is the number the bank sees.
  • Total project cost — contract sum + soft costs + land + developer fee, marketing and closing. Internal underwriting only.

Every saved budget also writes a normalized schedule-of-values table that the Master Lender Package pipeline reads later, so the line items you set here become the SOV rows in the lender package.

A saved budget can also be underwritten: the Investment Analysis tab turns it into a five- or ten-year before-tax investment model — operating cash flows, financing, hypothetical sales, and investor returns — described in its own section below.

Statuses

Budgets and investment analyses share one status workflow: Draft (gray), In Review (amber), Completed (green), and Cancelled (red). The status chip is clickable wherever it appears — list rows, cards, the budget editor's Status field, and the analysis editor's chip — and picking a new status saves immediately without creating a budget version. Older budgets marked Finalized display as Completed.

Search Everywhere (Cmd/Ctrl+K)

Cmd+K (or Ctrl+K) opens a search popup from any page. Type any part of a project ID, budget name, or analysis name; results list budgets first, then investment analyses. Arrow keys move the selection, Enter opens it, Esc closes. Both Home lists also have their own search box, status filter, and grouping — budgets and analyses alike.

Settings

Click your avatar in the header and choose Settings. Everything there is saved to your account, so your choices follow you to any browser you sign into:

  • Profile — a display name (used in version history and "created by" lines; it defaults from your sign-in identity) and a phone number. Email is shown but locked to the account you are signed in with.
  • Theme — Light (the default) or Dark.
  • Theme Pack — super admins only: Finishes Solutions (the default) or Editorial, an alternate look for the whole suite. A pack changes appearance only — every page, control, label and number stays exactly where it is — and it brings its own accent color, so the Accent Color choice below applies while the Finishes Solutions pack is selected.
  • Accent Color — Green (the default), Blue, Violet, Graphite, Red, Orange, or Custom: the rainbow button opens a color picker and the app derives a full light and dark palette from whatever color you choose.
  • Profile Icon Background — six preset colors behind your header initials, or the rainbow swatch for any custom color.
  • Time Format — 12-hour (8:52 PM) or 24-hour (20:52) for every timestamp.
  • Views — three options per section: a Comfortable list, a Compact list, or Cards — chosen separately for Projects, Project Budgets and Investment Analyses (a roomy budget list next to analysis cards is fine). The same three-way icon toggle sits above each list.
  • Exports — the Remember Export Settings toggle: on, the sections and options you pick in the export popups (budget and analysis separately) become your defaults everywhere you sign in; off, every export starts from the standard defaults.

Preference choices apply immediately and save quietly; profile fields save with their button. Printed reports and PDF exports always render in light, whatever theme the screen uses.

Projects

The Projects tab is the parent view. One project per ID, and everything that belongs to it hangs off its page: the budgets, the investment analyses built from them, and whatever you have starred.

Create one with + Create Project on the Projects tab: an ID, a name and an address. A project has no type of its own — each of its budgets carries one, so a single property can hold a Multifamily budget and a Commercial budget at the same time. From a project page you can:

  • Add a budget — + New Budget asks which template to start from, then which project it belongs to, and carries that project's name and address across.
  • Add an alternate budget — a copy of the base budget under a suffixed ID (BD-0001-02), for pricing the same project a different way. It opens unsaved so you can change it before keeping it.
  • Choose the primary budget — Make Primary in a budget row's three-dot menu. Exactly one budget is primary, and Total Project Cost (Primary) reports that budget alone; an alternate is another way of pricing the same work, so it is never added in.
  • Move it through the pipeline — Lead, Qualified, Budgeting, Proposal Sent, Awarded, and finally Converted to Project, with On Hold and Lost for everything else.
  • See what you starred — the Favorites strip shows only the budget and analysis you starred on this project, rather than everything that exists.
  • Add an investment analysis — + Add Investment Analysis on the Investment Analyses card. With one budget on the project it links to that budget without asking; with several it asks which one, offering only this project's budgets.
  • Act on a row — the three-dot menu at the end of each budget row carries the same Edit, Versions, Update Pricing and favorite actions as the Budgets tab, plus Make Primary; each analysis row carries the analysis menu (Open, Versions, Duplicate, Delete and its favorite toggle). Project rows on the Projects tab carry their own menu: Open, Favorite and Delete Project.
Deleting a project takes its children with it. Delete Project flags the project, its budgets and its investment analyses as deleted in one step, and says how many before it does. Nothing is destroyed — every saved version is kept, and an administrator can restore it.
Converting captures the numbers. Moving a project to Converted to Project records the contract and total project amounts from its primary budget at that moment. They stop moving when the budget is edited afterwards, which is what makes the Analytics totals a stable record of work won rather than a figure that drifts.

Project and Budget IDs

A project is a number. Everything else — its budgets, its investment analyses — is a labelled attachment to that number. 0042 is the project; OP-0042 is how it reads on screen; BDG-0042-01 is its first budget; INA-0042-01 is its first investment analysis. The prefix says what kind of record you are looking at; the number says which project it belongs to; the last two digits count the items within it.

OP-####Project — e.g. OP-0042. Unique among live projects: deleting a project frees its number for a future one, but two live projects never share it.
BDG-####-##Budget — project number + item number, e.g. BDG-0042-01, BDG-0042-02. The ID is suggested automatically from the project you pick, so a budget carries its project's number without anyone lining them up by hand.
INA-####-##Investment analysis — same shape, shown wherever the analysis appears. A display label: the record itself is tracked internally, so this can never collide.
BD-#### / OP-#### / AS-####Older budget IDs from before the numbering model, including their -02… alternates. They open and save exactly as before; nothing was renamed, and their families keep numbering the old way.
TST-####Test data. Its own sequence — a test record never consumes a project number. Use TST-9999 when checking a preview build.

BDG-0042-01 and BDG-0042-02 are two budgets on project 0042 — the second is not an "alternate" of the first, just the next item. The number is allocation order, not importance: sort by dates, never by the number. An ID is a database key, so it cannot be corrected by renaming later without creating a second record — which is why new IDs are computed rather than typed.

Test budgets are real rows. Preview builds share the production database, so a TST- budget is written to the same tables as live projects. It is flagged with a Test badge everywhere it appears — delete it when you are finished.

Project

Residential buildable SF drives every line priced per residential SF — the bulk of the budget and most soft costs. Amenity / clubhouse SF drives the amenity scope at its own, higher rates, because the model prices the two buildings separately.

Unit Mix & Rent Revenue

One row per unit type. Type SF, monthly and yearly revenue are calculated. Two behaviors worth knowing:

  • Editing $ / SF / mo works backwards and sets rent to SF × your rate, matching the direction the source spreadsheet calculates.
  • The badge in the card header shows an efficiency percentage — explained below.

What Efficiency Means

Efficiency is the share of the building you can actually rent:

efficiency = total unit SF ÷ residential buildable SF

Total unit SF is every unit type's SF multiplied by its count — the leasable area. Residential buildable SF is the whole structure. The gap between them is everything you build but nobody rents: corridors, stairwells, elevator shafts, lobbies, walls, mechanical and electrical rooms, trash rooms.

It matters because you pay to build the whole number and collect rent on only part of it. Two buildings of identical size at different efficiencies produce different revenue from the same construction cost, so it is one of the earliest signals of whether a layout works.

Typical rangeGarden-style walk-ups tend to run high, often 85% or better, because they have little interior circulation. Mid-rise with double-loaded corridors and elevators usually sits lower. What counts as good is specific to the building type — compare against your own past projects rather than a rule of thumb.
Reading it lowEither the design carries a lot of unrentable area, or the unit mix is incomplete — a missing unit type or a wrong count will understate leasable SF and make an ordinary building look inefficient.
Amber warningUnit SF exceeds residential buildable SF, which cannot be true. Almost always a typo in a unit count or SF, or a residential SF figure that was never updated after the design changed.

Amenity SF is deliberately excluded from this calculation. The clubhouse is not rentable area, and it is measured and priced separately.

Site Efficiency, and How It Differs

Building efficiency asks how much of the structure you can rent. Site efficiency asks how hard the land is working:

site efficiency = (residential SF + amenity SF) ÷ total site SF

That is the floor area ratio, expressed as a percentage. Enter the land area in Total Site SF or Site Acreage — they are the same measurement (43,560 SF per acre) and each fills the other — and the Project card reports site area in acres, site efficiency, density in units per acre, and building efficiency side by side.

What it tells youWhether the scheme is using the parcel you are paying for. A low figure on expensive land is the earliest sign that the deal needs more density, or that the land is priced wrong for what will fit on it.
DensityUnits per acre, the number entitlement and zoning conversations are usually conducted in. It comes from the same site figure, so it appears as soon as you enter one.
Over 100%The tile turns amber. Building SF exceeding site SF is normal for anything multi-storey — a two-storey building covering half the site is already 100%. Read it as a ratio, not a ceiling; it is only a warning when you expected a single-storey scheme.

Total site SF prices nothing. It never touches a rate, a quantity or the contract sum — it exists purely to produce these measures, so leaving it at 0 costs you nothing but the metrics.

Other Income and Operating Expenses

Enter gross charges under Other income — what the resident is billed. Put the cost of providing them under Operating expenses. The tool nets the two and reports net other income.

  • A green ● next to a count means it tracks total units automatically. Type over the count to break the link — useful for parking spaces, pet rent or premium units that apply to only some units.
  • Expenses are per unit or fixed / mo. Fixed lines apply once no matter the unit count.

Profit & Contingency

Profit is a percentage of construction hard cost, per company; add a row for each entity taking a fee. Contingency carries three ways — percent of hard cost, dollars per SF (residential + amenity), or a fixed amount. It is always reported as its own line, never blended into the trades.

The Budget Page

Lines are grouped into three scopes — Residential Construction, Amenity / Clubhouse and Soft Costs — and then into phase groups within each. Click any scope or group header to collapse it; subtotals stay visible. Collapse all is the fastest way to sanity-check the shape of a budget.

Quantities

A green ● on a quantity means it is derived from the inputs, so it follows your SF and unit counts automatically:

per amen SFQuantity = amenity SF

Undo & Redo

Cmd+Z (or Ctrl+Z) undoes your last committed change — a deleted line item comes back, an edited rate or quantity reverts — up to ten steps. Cmd+Shift+Z (or Ctrl+Y) redoes what you just undid, also up to ten steps; making a new change after an undo clears the redo path, like any desktop application. One step is one change, not one keystroke. The history is deliberately small and in memory only: it clears when you open another budget or reload the page, and it never touches saved versions. If you are typing in a field when you press it, the field commits first and that edit is what gets undone. The same shortcuts work in the investment analysis editor: with an analysis open they act on the analysis inputs instead of the budget, with the same ten-step history.

Manually Edited Lines

A blue dot to the left of a line means you changed it rather than taking the library's number. A line is marked when you override its quantity, set a rate that differs from the pricing library, change its description or basis, or add it by hand. Hover the dot to see which of those applied. The count of edited lines sits in the card header.

Put a rate back to the library figure and the dot clears itself, so the marks stay honest. They also travel into the Excel export, which carries a Manually edited column alongside the original library rate — useful when someone asks which numbers came from the model and which came from judgment.

Scopes, and How They Relate to CSI Codes

Every line belongs to one of three scopes. The scope answers where the money goes; the CSI code answers what the work is. They are independent, which is why the same code legitimately appears more than once.

Residential ConstructionThe apartment buildings themselves. Priced against residential buildable SF. Inside the construction contract.
Amenity / ClubhouseThe clubhouse and leasing building. Priced against amenity SF at its own, higher rates. Also inside the construction contract.
Soft CostsDesign, engineering, permits, impact fees, contingencies on those. Priced against residential SF, but outside the construction contract — it is part of total project cost only.

So Residential + Amenity = construction hard cost, which becomes the contract sum once profit and contingency are added. Soft costs never enter that number.

No clubhouse? Set amenity SF to 0. The amenity scope then disappears from the budget, the CSI schedule and both exports, and stops contributing to the contract sum — including any amenity line you had set to a lump sum or given a manual quantity, which would otherwise keep adding money you could no longer see. Nothing is deleted: put a figure back in amenity SF and the whole scope returns exactly as it was.

Why the Same CSI Code Appears Twice

Take 09 60 00 Flooring. It exists in the residential scope at one rate and in the amenity scope at a much higher one, because clubhouse flooring is a different specification from apartment flooring. One CSI code, two scopes, two rates — that is correct, not a duplicate. On the CSI schedule both lines sit under Division 09 with a Residential or Amenity tag telling you which building each belongs to.

Soft costs use SC-## codes rather than CSI codes, because MasterFormat classifies construction work results — it has no home for an architect's fee or a traffic impact study. That is the second reason they are reported separately on the schedule.

Scope and Basis When Adding a Line

The scope dropdown in the CSI picker sets the quantity basis for you: choosing Amenity gives the line per amen SF, anything else gives per res SF. Change it afterwards with the Basis dropdown if the line should count per unit or be a lump sum instead. Getting the scope right matters beyond bookkeeping — it decides which square footage drives the quantity, and whether the money lands inside or outside the number the bank sees.

Adding Scope

+ Add Line Item opens the CSI MasterFormat catalog. Adding from the catalog means the line carries a real code into the SOV, which the lender package depends on. New lines arrive at rate $0 — set the rate before you trust the total.

The catalog is the same MasterFormat list wherever you open it — the fields above the search box decide where the new line goes, not what you can pick from.

Add To is the scope: whose cost the line is. The CSI code says what the work is; the scope says which bucket the money lands in — and the same code can legitimately appear in more than one scope. The standard template prices 28 46 00 Fire Detection & Alarm twice: once for the residential building and once for the clubhouse, at different rates.

Residential ConstructionPriced against residential SF by default. Rolls into hard cost and the contract sum.
Amenity / ClubhousePriced against amenity SF. Rolls into hard cost — but when amenity SF is 0 there is no amenity building, and the whole scope contributes nothing.
Soft CostsOutside the construction contract sum. Joins at total project cost, and is reported separately on the SOV.

Group picks the heading the line files under:

An existing groupThe line is filed under that heading — pick Site Finish and it lands with the other site finish lines instead of starting a section of its own. The list shows only groups already in use for the chosen scope, so it follows the Add To dropdown.
AutoThe default. The line is filed under its CSI division, creating a heading such as "Division 14 — Conveying Equipment".
New group…Reveals a New Group Name box so you can type your own heading, for scope that does not belong anywhere existing.

Lines are inserted next to the group they join rather than appended at the end, so a group never appears twice in the budget or in the exports.

Reading the Summary

The left column walks hard cost up to contract sum, then adds the non-contract costs to reach total project cost. The right column is the SOV rollup: the same money grouped the way it will appear on the schedule of values, with contingency shown explicitly as line 99.03 and profit broken out by company.

Guard Rails

Every budget is measured against a set of ratios — the Guard Rails card at the bottom of the Budget page lists each one, what it measures, where it currently sits, and the range it is expected to fall in. The pill beside Margin and Gross yield tells you at a glance whether anything needs looking at.

Most rails only flag. Three of them refuse the save:

  • Operating expenses must be between 35% and 55% of gross income. A multifamily budget outside that band is almost always missing whole categories of cost — taxes, insurance, management, payroll — rather than genuinely being cheap to run.
  • Fee percentages — developer fee, marketing and closing together — cannot exceed 95% of total project cost. Above that the arithmetic that resolves them stops having a sensible answer.
  • Leasable unit SF cannot exceed residential buildable SF, which cannot be true.

A rail is only checked once the numbers it divides actually exist, so a half-built budget is never blocked. Budgets created before the full expense schedule shipped are warned rather than blocked on the 35–55% rail, and the card offers Update Expense Schedule to append the missing categories at $0 for you to fill in.

Overriding a rail. A director or super admin can record an override with a written reason. The override is stored on the budget with your name and the date, shown on the summary, and printed on the PDF and the Excel workbook — it is a decision on the record, not a way to switch the check off. Bringing the value back into range clears it automatically.

CSI Schedule

The CSI schedule tab re-presents the same budget as a MasterFormat schedule of values: sorted by division number, grouped under Division 00–48 headings with a subtotal per division, showing the full code on every line. Same money as the Budget page, organised the way an architect, lender or general contractor expects to receive it.

  • Profit and contingency appear as Division 99 — Markups, with contingency carried explicitly as 99 03 00 and never blended into a trade line.
  • Soft costs are listed separately and are not part of the contract sum — the bank sees the construction contract, not the total project cost.
  • Hand-added lines with no CSI code collect under Uncoded / Custom Scope, a prompt to give them a real code before the budget goes out.

The Residential and Amenity tags on each line say which building the work belongs to, so a code that appears in both scopes stays readable. See The Budget Page for what the scopes mean and why a code can appear twice.

The schedule is also its own Excel sheet and its own PDF section, both selectable at export.

Pricing Library and Versioning

All rates come from one shared library so two people pricing the same building get the same answer. The important rule:

A budget snapshots the library the moment it is created. Publishing new rates never moves the numbers under an existing budget. Your saved work does not change behind your back.

When a budget is running on an older library, a banner appears on the budget page naming both versions. Update to current pricing pulls the new rates in — it matches on scope, code and description, so standard template lines are repriced and any custom line you added keeps the rate you gave it. Quantities are untouched, but a rate you changed by hand on a standard line is replaced by the library rate (the confirmation says how many were). The banner's × hides it for that budget while you work; the reprice stays one click away in the Home list's three-dot menu as Update Pricing (which simply confirms when a budget is already current).

Publishing is the other direction: an admin edits the library and publishes, which stamps a new version number and effective date. Only budgets created after that point pick it up.

Investment Analysis

The Investment Analysis tab turns a construction budget into a five- or ten-year before-tax underwriting model: operating cash flows, financing, hypothetical sales, and the returns an investor would look at — cash-on-cash, DSCR, equity multiple, IRRs, leverage, and an acquisition-price sensitivity table.

Starting one. Press + New Investment Analysis — on the Home page or the Investment Analysis tab, both open the same popup. Pick From Existing Budget to link the analysis to a project (it is created from that project's latest saved budget version), or Standalone Analysis for one unlinked to any budget — name it there, or leave the name blank and rename it on the first step. A linked analysis imports the property name and address, the size, the unit mix, gross scheduled rent (unit rents × 12, never the budget's net income figure), other-income rows, and the total project cost as a suggested purchase price. Every imported value shows a green From Budget badge and stays fully editable — editing a value away from the import hides its badge, and restoring the exact imported value brings it back, even after saving and reloading. In the lists, the Project / Budget column shows which budget version a linked analysis came from (for example, BD-4821 v14) — distinct from Analysis Ver., which counts the analysis's own saved versions.

The import is a snapshot, not a live link. Each analysis records the exact budget version it came from. Changing the budget later never changes the analysis.

The six steps. Work left to right: Source & Property, Income, Vacancy & Expenses, Mortgage, Disposition, then Review & Report. Each step ends with a Next button that lights up green when the step's required fields are filled, and completed steps earn a checkmark on their pill. Three things are never guessed for you and must be entered: the purchase month, the property's complete operating expenses (the budget's service-expense rows appear as a partial reference only), and the exit cap rate. Financing is either all cash or one fully amortizing first mortgage entered as dollars or LTV. The projection runs five or ten years — pick on the first step.

Calculate and Save. Calculate sends the assumptions to the server and shows the report; the browser never computes results itself. Editing any input marks the result stale until you recalculate. Save (or Cmd/Ctrl+S) recalculates and stores the analysis — every meaningful save records an immutable version, and a save that changed nothing records none, exactly like budgets. If someone else saved the same analysis after you opened it, your save is refused with the option to reload their version.

Versions. Open version history from the three-dot menu on an analysis row — on the Home page list or the Investment Analysis tab — the same way budget versions work. Old versions open read-only, exactly as calculated when saved, and are never recalculated by newer formulas.

Reading the report. A few conventions worth knowing: a sale at the end of a year is priced on the following year's income at the exit cap rate, rounded to the nearest $1,000, and selling costs and the loan payoff come out of that rounded price. Leverage compares the equity IRR against the unleveraged property IRR — positive leverage means borrowing raised the return. The optimal holding period is simply the sale year with the highest equity IRR.

Exports. Export works like the budget's: pick which sections to include, set the options, then choose the format from the shared button row. The analysis-specific options: Highlight Key Metrics puts a light green highlight on the PDF's gross operating income, net operating income, purchase price, initial investment, equity multiple, cash-on-cash and IRR rows so they stand out at a glance, and Signature Needed appends the identified approval page described under Exports. Saved analyses can also be fetched straight from the API as pdf, xlsx or csv via /api/investment-analysis/<id>/export?format=…. Every export is built from the calculated result — never the screen — and the Export button is disabled while the result is stale, so an export can never disagree with the assumptions. The full editor works on phones and small screens too — wide tables scroll sideways inside their card.

Exports

Every export popup in the suite works the same way: tick which sections to include, set the options, then choose the format from the same button row — Email (Soon), Print, PDF, Excel (.xlsx). Only the section checkboxes differ between budgets and investment analyses.

Excel (.xlsx)A branded workbook, one sheet per section. Every sheet opens with the Finishes Solutions title band, table headers freeze, currency and percentages carry real number formats, and every sheet prints landscape and fits to width. Values are live numbers, not text, so they can be pivoted or re-totalled.
PDFThe direct branded PDF download — a real file, no print dialog, on budgets and investment analyses alike. Portrait letter with generous margins, composed by the same document renderer both products share.
PrintA composed report rather than a picture of the screen: logo lockup, project header, key metrics band, then whichever sections you ticked. Collapsed groups never affect it — the report is always complete. Opens the browser print dialog; choose "Save as PDF" there for a file.
EmailMarked Soon — sending exports by email is planned but not built yet.

Signature Needed

Tick Signature Needed in the export options and the PDF (and the printed report) ends with an approval page: a signature line and a date line, above an identification block naming the exact document being approved — the project or analysis, its key money figures, its saved version, and when it was generated. The identification is the point: a signed approval page cannot be detached and combined with a different budget or analysis, because the page itself says precisely what was signed for. An approval page whose identification does not match the document it accompanies is void, and the page says so.

Every export reads the same numbers the screen shows, so exports cannot drift from the saved document. The budget workbook also carries the Manually edited flag and each line's original library rate.

Download Guide, at the top of this page, downloads a formatted PDF of this guide through the same rendering engine as every other export. It is generated from this page rather than a separate copy, so it cannot fall out of date with what you are reading.

Timestamps

Every date and time the app shows — the Updated columns, version history, save stamps, and the Generated stamps on exports — is your local time, formatted MM-DD-YYYY h:mm AM/PM (for example, 08-17-2026 8:52 PM). Times a document was saved on another machine display in YOUR timezone when you view them.

Who Can Do What

Application Roles

Every user who signs in gets a default application role. Roles control which budgets and analyses you can see in the list view. A super admin can change any user's role from the Admin page.

User (default) Can create, edit, save, delete and export budgets and investment analyses. Sees only budgets and analyses they created.
Manager Same as User. Sees only budgets and analyses they created. Intended for team leads who do not need visibility into other teams' work.
Director Can see all budgets and analyses across the organization, regardless of who created them.
Super Admin Everything Director can do, plus access to the Analytics dashboard, the Admin page for managing user roles, the Theme Pack setting, and any platform administration features.

Platform Roles

Platform roles are assigned through Azure and control access to specific features beyond the application role.

pricing_adminCan edit and publish the pricing library. This is deliberately a very short list, because a rate change affects every budget created afterwards.
super_adminGrants Super Admin application role automatically. Required for the Analytics dashboard and Admin page. The pricing page shows whether your account holds this role.

If you need a role change, ask a super admin or the tool owner.

Troubleshooting

A red banner says the server cannot be reached Saves will fail and rates shown may be the built-in fallback rather than the published library. Reload. If it persists, the API or database is down — report it before doing more work, and copy anything unsaved out first.
The first request of the day hangs The database pauses when idle and can take a couple minutes to resume — the loading screen keeps you posted while it wakes. If a request still hangs after that, retry once.
Publishing pricing returns "not authorized" Your account does not hold pricing_admin in this browser profile. Check /.auth/me; if the role is missing, the role invitation needs to be accepted in the profile you are actually signed in with.
Sign-in loops back to the login page Usually the address you are using is not registered as a redirect URI — common on a preview build. Send the URL to whoever set up the environment.
A budget shows $0 totals Almost always residential SF is 0, or every line was switched to lump sum with no rate set.
I deleted a line by accident Cmd/Ctrl+Z restores it — up to ten changes back, while the budget stays open. Cmd/Ctrl+Shift+Z (or Ctrl+Y) redoes an undo.
I lost my edits Nothing autosaves. The header pill shows unsaved state and the browser warns before closing — if that warning was dismissed, the work is gone. While the budget is still open, Cmd/Ctrl+Z steps back up to ten changes.

Reporting a Problem

The Report a Bug button sits in the bottom-left corner of every page. Pick whether something is broken or something is missing, and your email app opens with a message to Matthew already written: the subject filled in, and the details underneath — which page you were on, which pricing library and engine you were running, your browser and screen size. You describe it in your own words and press send. You can see exactly what will be attached before you pick. Nothing from your budgets or analyses is included.

For a bug, say what you did, what happened, and what you expected — those three lines are usually enough to reproduce it. If your machine will not open a mail app, Copy Details puts the same message on your clipboard to paste anywhere.
