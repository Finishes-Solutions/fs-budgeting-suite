# Decisions — budgeting-v2 upgrade

One line per decision: what was chosen and why. Newest at the bottom.

| # | Date | Decision | Reason |
|---|---|---|---|
| D1 | 2026-10-24 | The "pro forma engine" is the investment-analysis engine `api/shared/investment/` (`calculateInvestmentAnalysis`, `before-tax-1.1.0`). Goldens freeze its full output for 7 deals. | It is the only pro forma in the suite; the budget's own income/opex math is part of the budget engine. |
| D2 | 2026-10-24 | Goldens were captured on staging @ 63ef1a4 before any merge or code change, then verified after merging `feature`. | "Before changing any code" — merging a branch changes code. |
| D3 | 2026-10-24 | Merged `origin/feature` (staging + site-wide pass #19 + the vigilant-cerf assistant/security work) into the upgrade branch. | It is the newest line, 0 commits behind staging, includes real fixes (stored XSS via row ids, save integrity, expense-ratio derivation) and the input-driven defaults work; `matthew/adoring-gauss` and `matthew/vigilant-cerf` are fully contained in it. |
| D4 | 2026-10-24 | Did NOT merge `claude/budgeting-suite-expansion-lwuc2e` (entities, financials, approval, contracts). | Different product scope, adds three schema migrations against the shared production database, was never merged into `feature` by the owner, and is 3 commits behind staging; bringing it to staging is the owner's call. Listed in PROGRESS "Things I need to do". |
| D5 | 2026-10-24 | Research lives in `data/research/**.json` (sourced evidence + defaults), validated by `tools/validate-research.js`, compiled by `tools/build-research-data.js` into `app/research-data.js`. | `app/` is the only deployed folder and there is no build step at deploy time; a committed generated bundle (test-enforced fresh) keeps "no build step" true while keeping research human-editable. |
| D6 | 2026-10-24 | Every money value carries its dollar year and region; one script escalates to 2026 and converts to a national baseline using `_indices/escalation.json` and `_indices/regional.json`. | One documented, repeatable normalization instead of each researcher adjusting by hand. |
| D7 | 2026-10-24 | Research was split across 15 parallel sub-agents: 11 by project category (residential and commercial split in two), plus indices/financing, soft-cost/fee norms, and two building-block researchers. | Category agents as requested; shared norms and blocks are used by every type, so they needed owners. |
| D8 | 2026-10-24 | "Baseline hard cost" is defined as the contractor price for a typical project incl. general conditions, OH&P and typical on-site work; excludes land, soft, FF&E, off-sites, impact/tap fees, financing. | Sources quote different scopes; one definition makes types comparable and lets the engine add the excluded pieces as their own lines without double counting. |
| D9 | 2026-10-24 | CSI MasterFormat divisions are the split vocabulary for every type, including site-centric ones (31–35, 48 cover civil, marine and power). | One vocabulary reconciles with the existing CSI schedule and the lender SOV. |
| D10 | 2026-10-24 | An estimate is **materialized** into ordinary budget fields (lines, contingency amt, projectCosts, engineSummary); `parts()`/`budget-calc.js` are unchanged. | Same seam as the Impact Fees line: SOV, CSI, versions, guard rails and classic exports keep working with no second implementation of the math; invariant `parts(doc).project === engine total` is tested for every type. |
| D11 | 2026-10-24 | Engine lines are `basis:'ls'`, qty 1; quantity × rate stays in the engine detail and exports. | The classic basis labels (Per Res SF / Per Unit) would mislabel keys, pads, MW…; lump sums are honest in the SOV. |
| D12 | 2026-10-24 | Guard-rail policy unchanged; estimates trip no blocking Multifamily rail and the v2 page shows the researched range check instead of the classic rail panel. | Changing `policyForType()` fallback would change save behaviour for existing custom-template budgets. |
| D13 | 2026-10-24 | The API's "building SF required" check also accepts an estimate sized in primary units (`engineSized`). | RV parks, solar farms, marinas have sites/MW/slips, not SF; the pro forma imports those units. Not an access control. |
| D14 | 2026-10-24 | Revenue for the pro forma is user input on each component; no researched rents. | Rents were outside the research brief; inventing defaults would violate the no-fabrication rule. |
| D15 | 2026-10-24 | Construction duration by Census C30 type × value band (and NAHB for single-family). | Authoritative public data; duration drives escalation midpoints and interest. |
| D16 | 2026-10-24 | The type soft-cost % EXCLUDES impact fees, developer fee, financing and contingency; 27 research values were adjusted in the second pass, with notes. | Several researched percentages included them and the engine adds each separately — double counting. |
| D17 | 2026-10-24 | Single-family and water/sewer fee norms recalibrated to NAHB 2024; Duncan 2019 kept as evidence for the high end. | Duncan covers only fee-charging jurisdictions; escalated, it doubled the national average. |
| D18 | 2026-10-24 | A saved estimate is never re-priced on open; research and engine versions are pinned on the document; a banner offers "Update to current research". | Budgets reach lenders; numbers must not move silently. |
| D19 | 2026-10-24 | The 2 MB research bundle loads on demand (`FSBudgetV2.ready()`), with loading and error states. | Classic budgets and every other page should not pay for it. |
| D20 | 2026-10-24 | Sample revenue, land and exit caps are labelled illustrative inputs. | Needed to run the pro forma; not research. |
| D21 | 2026-10-24 | The `design:accessibility-review` and `design:design-system` skills failed to load; substituted an axe-core WCAG 2.1 A/AA audit (`tools/a11y-audit.js`, axe-core as a dev dependency) and a manual token review. | Objective, repeatable, covers light and dark themes. |
| D22 | 2026-10-24 | "Lint/typecheck" for this no-build JS codebase = `tools/check-syntax.js` (parses every first-party script incl. inline HTML scripts) + the research validator; no TypeScript added. | The repo has no TS or linter; adding one is out of scope and the ground rule's real risk is a syntax error shipping. |
| D23 | 2026-10-24 | A pro forma whose component/phase no longer exists is refused (409) rather than turned into a whole-project analysis. | Silent scope changes alter purchase price. |
| D24 | 2026-10-24 | New Budget rows are selected by `data-tpl` in tests and tools. | Copy is not a selector. |
| D25 | 2026-10-24 | Pushing `staging` (the requested final step) triggers the existing staging deploy workflow; no other deploy was run and no migration is needed. | The owner's instruction is to merge and push `staging`; the workflow is theirs. Nothing in this upgrade requires SQL. |
